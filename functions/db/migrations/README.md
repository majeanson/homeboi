# D1 migrations

Forward-only, additive, **filename-locked** — wrangler tracks applied state by
filename, so never rename a migration that has run. No rollback path: ship a
forward fix.

- `npm run db:migrate:local` for dev.
- `npm run db:migrate:prod` to push to the remote D1.

| File            | What it adds                                                                                                                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0001_init.sql` | Everything: households/domains/operators/members, device pairing (devices + pairing_codes), captures, events/tasks/list_items, meals/pantry_low, routines/routine_runs. Deliberately no streaks/points/push tables. |
| `0134_operator_session_version.sql` | `operators.session_version` — the counter the session cookie's `v` is checked against; bumped by a reset, a password change or « Se déconnecter partout ailleurs » (STATE.md §4-L L1). |
| `0144_meal_ideas_sample_flag.sql` | `meal_ideas.is_sample` — lets the demo sandbox seed two « Idées de repas » that the `SAMPLE_TABLES` sweep can clear (stranger review 2026-10-23). |
| `0153_task_kind_shrink.sql` | `kind` is `plan` · `upkeep` · NULL: a chore and a loose to-do become NULL, one plain task. Rebuilds `home_projects` (the 0150 shape, ids kept) with a nullable `kind`, no default, and a CHECK that refuses any other value. `at` is NOT touched: rewriting it to a household-local midnight needs each household's zone and its DST rules, which D1 does not have, so the Worker does it (`normalizeTaskDays`, `_lib/taskDay.ts`, the nightly cron, idempotent) and every reader decodes `at` meanwhile. Idempotent. `worker/taskKindShrink.d1.test.ts` (three zones, both sides of each DST change); a pre-0153 copy restores through `upgradeTasks`. |
| `0152_task_start.sql` | Every recurring chore with no start gets its `created_at` as `at` (the date every reader read the NULL as since 0032), so `at` reads one way for every task. Only `kind = 'chore'`, `at IS NULL`, and a recurrence `parseRecur` accepts (the LAST `freq`, via `json_each`, as JSON.parse). `kind` untouched. Idempotent. `worker/taskStart.d1.test.ts`; a pre-0152 copy restores through `upgradeTasks`. |
| `0151_tasks_window_sweep.sql` | The deploy-window sweep after 0150: moves into the spine any loose `todos` row an old Worker wrote between the migration and the deploy, with its id, the same mapping as 0150. Idempotent (a row already in the spine is not copied twice). Departure rows untouched. `worker/taskWindowSweep.d1.test.ts`. |
| `0150_tasks_one_table.sql` | ONE task table. Rebuilds `home_projects` (the spine: + `announce_evening`, `member_id` a to-do's author, `position`, a nullable `colour`), copies every `tasks` row (kind `chore`, `recur_start` → `at`) and every loose `todos` row (kind `todo`, `day` → `at`, `done_at` → `last_done_at`) with their ids, rebuilds `task_participants` with `task_id` as a soft ref, drops `tasks`. Departure checklists stay in `todos`. Drilled in `worker/taskMerge.d1.test.ts`; a pre-merge copy restores through `upgradeTasks` (`_lib/restore.ts`). |
| `0149_task_effort.sql` | `effort` INTEGER on `tasks`, `todos`, `home_projects` — 1 (tout simple) to 5 (gros effort), NULL = not said; bounded on write by `taskEffort` (`_lib/validate.ts`). « Trouver quoi faire » reads it, and a NULL shows under every effort. Never minutes, never a person. |
| `0148_task_look.sql` | `icon` on `tasks`, `todos`, `home_projects`, `pets` and a nullable `colour` on `todos` — a task's look, inherited from its subject and overridable (`lookOf`, src/lib/subjects.ts). A carnet's icon stays in `facts_json.emoji`. |
| `0147_task_layers.sql` | `cleared_at` on `tasks` + `home_projects` (« Effacer les cochées » before the day ends, the row stays as history) and `rotation_json` + `current_idx` + `last_done_by` on `home_projects` (rotation on any recurring task, the one path in `_lib/rotation.ts`). |
| `0146_task_subject.sql` | `subject_kind` + `subject_id` on `tasks`, `todos`, `home_projects` — « Sur quoi ? », the soft subject ref of a task. No FK on purpose; `home_projects.carnet_id` stays and reads as kind `carnet` (`_lib/subject.ts`). |
| `0145_usage_browser.sql` | `usage_daily.browser_renders` — the third daily-budget meter: Browser Run renders, the recipe import's headless-browser door (`_lib/renderPage`), 20/day per household, 5 for a sandbox. |
